Clef is being built in the open, on published research. The toolchain is still being assembled, so this section is where to follow the project: where the compiler and language stand today, and the research underneath the design.

For the current state and the ways to engage now, see [Getting Started](/docs/guides/getting-started/). The [language specification](/spec/draft/) and [design rationale](/docs/design/) are the site's most developed material.

## A Deeper Dive - arXiv Pre-Prints

Beneath the entries on this site around design sits a foundational sequence of preprints, formal treatments of key ideas and concepts this site describes in prose.

1. **[Dimensional Type Systems and Deterministic Memory Management](https://arxiv.org/abs/2603.16437).** (DTS+DMM) The foundation, and the reason Clef needs no `unsafe` escape hatch: memory safety is settled at build time. Kennedy-style dimensional types make the code self-describing, so the annotation a developer reads to understand a value is the one the compiler reads to fix its numeric representation and memory layout. Those annotations survive multi-stage MLIR lowering, so representation and deterministic allocation resolve together, as coeffects of our program semantic graph.
2. **[The Program Hypergraph](https://arxiv.org/abs/2603.17627).** (PHG) Clifford algebra is the shared language of classical geometry and quantum gates, and its geometric product carries a Cayley table that runs 85 to 95% structurally zero. Our hypergraph makes grade a dimension axis in the type system, so the compiler derives the non-zero Cayley entries from type signatures alone and eliminates the rest before code generation. The same grade and hyperedge structure that prunes a physics kernel is designed to carry unitarity and multi-qubit gates in a quantum-classical setting.
3. **[Adaptive Domain Models](https://arxiv.org/abs/2603.18104).** (ADM) Our training architecture keeps memory bounded and geometry intact. It trains in forward mode with stack-allocated gradients and exact posit accumulation, so geometric invariants survive training, and posit arithmetic puts that training within reach of hardware conventionally reserved for inference, including neuromorphic targets.
4. **[Decidable By Construction](https://arxiv.org/abs/2603.25414).** (DBC) This is a keystone paper. It frames the three preceding papers into one claim: the properties that make a model numerically stable and domain-consistent are decidable in polynomial time, before training begins. What it adds beyond composing them is an information-theoretic result: Hindley-Milner unification over those abelian-group constraints computes the maximum a posteriori hypothesis under a computable restriction of Solomonoff's universal prior, placing our type inference on the same formal ground as universal induction.
5. **[Fixed-Point Scaffolding](https://arxiv.org/abs/2606.02854).** (FPS) Y-Combinator is more than a catchy name of a tech financier. We use well-established algebra to bring new capabilities to MLIR's C++ based undercarriage.The formal structure of Huet's zipper and Petricek's codata/coeffect formalism sequences our compiler's lowering passes, carrying grade, escape, and representation annotations through MLIR. The best part is the formal construction stays an internal scaffold. At design-time the developer gets the guarantees, while the category theory stays inside the compiler. 
6. **[Negative and Fractional Types](https://arxiv.org/abs/2606.04352).** (NFT) Here we extend the Fidelity Framework type system with additinal duals that bear particular novel utility: negative types for backward information flow, fractional types for resource division, both first-class. Built on the James-Sabry dualities in compact closed categories, the same Kennedy-styled abelian-group structure keeps this inference decidable, with negative and fractional types participating as principal types. This admits use cases for type-level support for Bayesian inference, quantum computation, and adiabatic computation that substantiates the unique utility that the Fidelity Framework can bring to the world of native computation.

Read together, (and we admit, it's *quite* a bit of reading) the six are one program. A single type system carries dimension, grade, reversibility, and proof from source through MLIR to whatever processor runs the code. Two threads run through them. The first is an avenue for **continuous learning** in AI model building and inference. The second is geometric and quantum: Clifford algebra gives the compiler the grade structure to position Clef as a language of choice for the landscape that will define the next era of compute. While it starts with humble beginnings garden-variety tasks and systems use cases, the language lowers to CPU, GPU, NPU, FPGA and IoT devices today, and shows it's reach to extend meet neuromorphic, quantum and other substrates that are on the horizon.
